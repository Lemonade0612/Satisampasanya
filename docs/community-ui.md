# Community feed and AI

Production posting and the assistant use backend/safety. The earlier keyword/enrichment module is retained for migration regression tests and is not imported by the live backend. NLLB handles translation only. DeBERTa is no longer used to invent evidence-based conversational results.

Hosted setup: put OPENAI_API_KEY privately in .env.local. OPENAI_MODEL defaults to the existing gpt-4.1-mini setting. The server rereads these private settings on requests; no key is sent to the browser or included in Git or Docker images. Docker receives the settings as runtime environment variables. Only configure LOCAL_HELPLINES with independently verified name/phone pairs. No phone numbers are fabricated. Responses use store:false and strict JSON schemas following https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses.

Auto routes through one model intent call. Ask gives a direct answer, 2–4 steps, an optional question and an offer to check the original message. It never calls moderation or returns verdict metadata. Check returns an approved, caution or needs_expert verdict. Reasons require an exact quotation from the original input, no more than eight whitespace-separated words and 120 characters. Invalid or unsupported results fail rather than inventing approval. Approved results have no reasons; caution has an edit suggestion. Lao or mixed input requires Lao prose; original evidence is preserved. UI language never changes the language of an existing answer.

Publishing streams read, links, patterns and verdict stages over a POST NDJSON response. These correspond to text validation, extracting links/numbers, awaiting the checker, and guarding its response. Link extraction is not an external reputation lookup. Progress reaches 100% only when the persisted post result is received. Caution remains visible. needs_expert freezes reactions, commenting and sharing until an authorised reviewer resolves it.

Open Launchers/Create Demo Users.command to check and seed the 13 community posts. The historical launcher name remains for compatibility. Running node scripts/seed-community.mjs --prepare creates unchecked posts while a key is unavailable; it never invents a verdict. With a key configured, the normal command checks every uncached post, stores the real result, and writes backend/data/checker-acceptance.json privately. --recheck forces fresh evaluations. _expect stays in the evaluation source/report and is never inserted into post data or returned to clients. Each seeded image is assigned once. Previous generated feed entries and conversations are archived in SQLite; actual user posts are preserved. Consistent snapshots are stored in ignored deployment/backups before changes.

The target is 13/13 verdict matches, grounded evidence, language-correct reasons and a direct Ask answer for the supplied Lao money-transfer question. Unit/integration tests with injected provider responses verify routing and guard behavior; they do not establish model accuracy. The real report must be inspected after the hosted key is configured. Missing keys, refusals, malformed output and provider errors are never replaced with fake verdicts.

Assistant limits remain 10 post checks and 20 text requests per account per Laos calendar day. Failed requests restore the allowance. Publishing is limited separately to 10 posts in a rolling 24 hours. Opening Launchers/Start iPhone.command builds bundled screens and starts the local backend; Vite is not required. Accounts/posts still require the backend to remain reachable.

## OpenRouter and expanded photo feed

AI_PROVIDER=openrouter selects https://openrouter.ai/api/v1/chat/completions. Put OPENROUTER_API_KEY privately in .env.local; OPENROUTER_MODEL defaults to openai/gpt-4.1-mini. OpenAI remains supported with AI_PROVIDER=openai. OpenRouter requests strict response_format JSON schemas and require_parameters:true so routing only uses endpoints supporting the requested output settings. Refusals, truncated responses and embedded errors fail instead of producing verdicts. Reference: https://openrouter.ai/docs/guides/features/structured-outputs.

The seed source now combines the original 13 acceptance cases with 10 additional photo posts. All 18 non-logo image assets are used once, including travel, fashion and political commentary that the checker may mark caution. The 13-case evaluator remains separate from these additional posts. Labels are never preset to create color variety. The three-color guide explains the meanings while model results are unavailable. BoonHome is restored as the primary Lao font, feed tabs are centered and larger, and the language toggle is a single globe button.

## Community reach and review workflow

The server computes a usefulness score for each post. AI-approved, on-topic text contributes 20 points; an approving/confirming human review contributes 30. Engagement contributes at most 30, using `round(4*ln(1+likes) + 6*ln(1+helpful) + 3*ln(1+unique commenters) + 4*ln(1+unique reposters))`. Counts come from persisted actions, exclude the author, and repeated likes remain idempotent. Stored display counts do not generate ranking points. Ranking divides `(score+10)` by `(1+ageHours/24)^1.2`. This is a reach score, not a probability that a claim is true.

Frozen, unchecked, caution and false-alarm posts cannot earn a boost unless an applicable reviewer decision clears them. For You prefers eligible posts, then followed accounts/topics, usefulness and freshness. Popular uses the age-adjusted usefulness rank; Latest remains chronological. The UI exposes the point breakdown.

AI checks post text and a separately supplied source URL before publication. An unchecked older post must pass the same server check before a reaction, comment or repost can succeed. Concurrent checks for the same older post share one request. A known verdict is reused; liking does not trigger repeated paid calls. Images are attached media; this checker does not claim visual fact verification.

High-risk posts keep their interactions locked pending review. Active reviewers and admins receive a persisted notification when review is requested and one reminder after 48 hours. The backend sweeps once per minute and on startup, including overdue work after downtime. Expiry never unlocks a post. Rejecting retains the original post, displays the correction note and keeps the lock. Approving can unlock it. Reviewer notices are internal app notifications, not external email.

Three more photos have separate captions, bringing the prepared set to 26 posts and 21 unique photo attachments. Typed contact details use `.invalid` links and all-zero phone numbers. Six images with printed contact details were edited with the imagegen skill to replace/remove those details. All other source photos were retained. Edited photos replace their source asset in the public directory and are not duplicated in the feed.
